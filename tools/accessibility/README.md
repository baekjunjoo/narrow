# VoiceOver·TalkBack 접근성 보조 점검

이 도구는 텍타일오디오의 주요 제어가 화면에 나타나고 이름과 역할이 연결되어 있는지, 일부 키보드 이동과 현재 화면 계층을 기록합니다. **자동 검사 성공은 VoiceOver 또는 TalkBack의 실기기 사용자 검증 완료를 뜻하지 않습니다.** 실제 음성, 스크린리더 포커스, 스와이프·VO 탐색, 동적 상태 알림은 아래 체크리스트로 직접 확인해야 합니다.

검사할 앱은 미리 실행해 두고 URL을 직접 지정하세요. 반드시 **공개해도 되는 테스트 주소와 빈 테스트 데이터**만 사용하세요. 이 도구는 원고를 입력·업로드하지 않고 오디오 생성, 파일 선택, 다운로드를 자동 실행하지 않습니다. URL 접속 자체는 해당 서버와 네트워크에 요청을 보냅니다. 브라우저 확장 프로그램, 웹 서버, 웹페이지의 자체 동작은 이 도구가 통제할 수 없습니다.

## 결과와 개인정보

기본 출력 위치는 시스템 임시 디렉터리의 `narravo-a11y-무작위값`이며, `--out-dir /기존/외부/폴더`를 지정하면 그 아래에 새 디렉터리를 만듭니다. **프로젝트 내부는 지정할 수 없습니다.** 새 폴더는 0700, 파일은 0600으로 생성합니다. 테스트 후 필요한 결과만 안전하게 보관하고 불필요한 폴더는 사용자가 삭제하세요. 공유하거나 Git에 올리지 마세요.

- `report.json`, `report.txt`: 항목별 결과와 사유. `PASS`는 그 자동 항목만 통과, `FAIL`은 해당 자동 확인 실패, `MANUAL`은 사람의 확인 필요, `SKIPPED`는 실행하지 않음을 뜻합니다.
- Safari: `dom-initial.json`, `dom-after-enter.json`, `keyboard-focus.json`. 이름과 역할, 가시성, DOM 포커스만 수집하며 입력값은 의도적으로 수집하지 않습니다. 그래도 접근 가능한 이름과 오류 메시지에는 민감한 정보가 포함될 수 있습니다.
- Android: `hierarchy-0.xml`부터 `hierarchy-3.xml`, `web-controls.json`, `keyboard-focus.json`. 기기 화면의 XML에는 **원고, 주소, 다른 앱/알림과 개인 정보가 포함될 수 있습니다.** `--screenshot`을 지정한 경우에만 화면 전체 `screen-0.png` 등을 추가로 저장합니다. 기기에 계층 XML을 임시 파일로 저장하지 않고 `/dev/tty`를 통해 호스트로 가져옵니다. 지원되지 않는 기기에서는 오류로 중단합니다.

종료 코드는 `0` 자동 검사에 FAIL 없음, `1` 실행된 자동 판정 중 FAIL 있음, `2` 인자·플랫폼·권한·의존성·기기 명령 등의 오류, `130` 사용자의 중단입니다. `0`이어도 MANUAL/SKIPPED가 남을 수 있습니다. 입력 단계에서 오류가 나면 결과 폴더가 만들어지지 않을 수 있습니다. 정리 실패는 MANUAL로 남으므로 결과 끝까지 읽으세요.

## macOS: Safari + VoiceOver

필요한 것은 macOS의 Safari, `osascript`, Python 3.9 이상, 이미 실행 중인 VoiceOver입니다. VoiceOver의 실행 상태는 macOS의 `NSWorkspace` 속성으로 사전 확인합니다. 스크립트는 VoiceOver를 켜거나 끄지 않습니다. [1]

1. 민감한 창을 닫고, Safari에서 **별도의 비공개 창**을 새로 여세요. 이 전용 창에 탭 하나만 남기고 주소를 `about:blank`로 설정하세요. 스크립트는 기존 다른 창을 조작하지 않으며, 실행 후 이 전용 창을 닫습니다. `--private-window-ready`는 이 조건과 창 종료에 대한 사용자 확인입니다. 비공개 모드 여부는 프로그램이 신뢰성 있게 확인하지 못합니다. 실행 중에는 기기를 만지거나 전용 창에 다른 탭을 추가하지 마세요.
2. VoiceOver를 직접 켜고 소리가 들리는지 확인하세요. macOS **시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용**에서 신뢰할 수 있는 터미널 앱에 접근성을 허용하고, 필요하면 **자동화**에서 Safari와 System Events 제어도 허용하세요. 신뢰할 수 없는 프로그램에 권한을 부여하지 마세요. [2]
3. Safari 설정의 고급에서 웹 개발자 기능을 표시한 다음, 버전에 따라 개발자용 메뉴 또는 개발 설정에서 **Allow JavaScript from Apple Events**를 사용자가 직접 켜야 할 수 있습니다. 이 기능은 다른 자동화 스크립트에도 영향을 줄 수 있으므로 원래 상태를 기록하고 테스트 후 원래대로 복구하세요. 손쉬운 사용·자동화 권한도 새로 허용했다면 테스트 후 직접 원래대로 되돌리세요. 이 도구는 설정을 자동 변경하지 않습니다.
4. 프로젝트 루트에서 아래를 실행하세요. 주소는 실제 안전한 테스트 주소로 바꾸세요.

```sh
python3 tools/accessibility/voiceover_safari.py \
  --url 'http://localhost:3000/' --private-window-ready
```

위 예시는 같은 Mac에서 테스트 서버가 3000번 포트로 실행 중인 경우입니다. 사용하는 서버 주소와 포트가 다르면 그 값으로 변경하세요. 페이지가 느리면 `--wait 20`처럼 1~60초를 지정합니다. 다른 폴더에 결과를 저장하려면 `--out-dir /tmp`를 추가합니다. `python3 tools/accessibility/voiceover_safari.py --help`에서 전체 옵션을 볼 수 있습니다.

스크립트는 빈 창과 VoiceOver 상태를 확인한 후 URL을 열고 제목·원고·예시 버튼·일괄 변환·품질 점검 제어의 DOM 역할과 이름을 검사합니다. 변환 바로가기 링크에 포커스를 놓고 실제 Return을 누른 다음 Tab을 세 번 보내고 DOM 포커스를 수집합니다. 링크 포커스의 초기 설정은 JavaScript로 수행하므로 전체 여정을 키보드만으로 수행한 증거는 아닙니다. 이름 계산은 일부 ARIA/HTML 규칙을 사용하는 **근사치**이며 Safari의 OS 접근성 트리 또는 VoiceOver가 실제로 읽은 내용이 아닙니다. Safari의 Tab 탐색 설정, VoiceOver 설정, 페이지 로딩에 따라 결과가 달라질 수 있습니다. 종료 시 전용 창의 탭이 추가된 경우에는 자동으로 닫지 않고 MANUAL을 기록합니다. 오류·중단 후 창이 남아 있다면 전용 창만 직접 닫으세요.

## Android: Chrome + TalkBack

호스트에 Python 3.9 이상과 Android SDK Platform-Tools의 `adb`가 필요합니다. 휴대폰은 잠금 해제되어 있어야 하고, USB 디버깅을 사용자가 켜고 컴퓨터의 RSA 연결을 직접 승인해야 합니다. `adb devices -l`에서 **device** 상태의 일련번호를 확인하세요. 아래 모든 명령은 `-s`로 한 기기만 대상으로 합니다. [3] TalkBack은 사용자가 미리 켭니다. 스크립트는 설정을 변경하지 않습니다.

1. Chrome에서 테스트 전용 **시크릿 탭**을 새로 여세요. 기존 데이터가 있는 탭을 사용하지 마세요. 시크릿 탭 여부는 스크립트가 확실하게 판별하지 못하므로 직접 확인해야 합니다. 다른 시크릿 탭을 함부로 닫지 마세요.
2. 전용 탭에서 주소창을 선택하고 기존 주소가 있다면 **전체 선택** 상태로 두세요. 키보드가 보여도 괜찮습니다. 포커스된 Chrome 주소창이 XML에서 확인되지 않으면 입력 전에 중단합니다. 화면이 꺼지거나 다른 앱으로 전환되지 않게 하세요. 실행 중에는 기기를 만지지 마세요.
3. 프로젝트 루트에서 자신의 일련번호와 실제 테스트 서버 주소로 바꿔 실행합니다. `192.168.1.10`은 형식 예시일 뿐 실제 서버가 아닙니다.

```sh
adb devices -l
python3 tools/accessibility/talkback_chrome.py \
  --serial 'YOUR_DEVICE_SERIAL' \
  --url 'http://192.168.1.10:3000/' \
  --incognito-address-ready
```

휴대폰의 `localhost`는 호스트 컴퓨터가 아니라 **휴대폰 자신**입니다. 휴대폰에서 접속 가능한 테스트 서버 주소와 포트를 따로 준비하세요. 현재 Android 자동 입력은 영문·숫자와 `: / . _ ~ -`만 포함하는 `http`/`https` URL을 지원하며 쿼리, URL 조각, 퍼센트 인코딩과 계정 정보는 거부합니다. `--wait 20`은 20초 로딩 대기, `--screenshot`은 민감한 화면 PNG 저장입니다. `--out-dir`과 `--help`도 사용할 수 있습니다.

ADB에서 활성 접근성 서비스 이름에 `talkback`이 있는지 먼저 확인합니다. 기기별로 서비스 이름이 다르면 실제 TalkBack이 켜져 있어도 자동 확인에 실패할 수 있습니다. 주소 입력 및 Enter 후 XML을 한 번 수집하고, Tab을 세 번 보내며 각각 XML을 수집합니다. Chrome WebView 내부에서 버튼·입력 등 역할과 이름이 함께 보이는 앱 제어를 찾습니다. 계층에는 화면 밖 콘텐츠, 웹 역할, 연결된 레이블 또는 TalkBack 커서가 생략될 수 있습니다. 누락된 개별 항목은 MANUAL이며, 기대하는 앱 제어를 하나도 확인하지 못하면 자동 검사는 FAIL입니다. `focused`는 일반 입력 포커스이지 TalkBack 접근성 포커스의 증거가 아닙니다.

스크립트는 다른 탭을 보존하기 위해 테스트 시크릿 탭을 자동 종료하지 않습니다. 끝나면 **해당 전용 탭만 직접 닫고** 원래 앱으로 돌아가세요. 테스트용으로 직접 켠 USB 디버깅도 필요 없다면 원래대로 되돌리세요. 시크릿 모드는 웹사이트나 네트워크 관찰을 막지 않으며 다른 시크릿 탭이 열려 있으면 해당 세션이 계속될 수 있습니다.

## 현장 수동 체크리스트

VoiceOver와 TalkBack 각각의 실제 기기에서 다음을 확인하고, 기기·OS·브라우저·스크린리더 버전과 결과를 별도로 기록하세요. VoiceOver의 VO는 설정에 따른 보조 키이고, TalkBack 제스처는 기기·설정에 따라 달라질 수 있습니다. [4]

1. 화면을 열 때 앱 제목과 주요 영역을 순서대로 알아들을 수 있는지 확인합니다.
2. VoiceOver의 VO+화살표 또는 TalkBack의 한 손가락 좌우 스와이프로 이동하며 포커스가 사라지거나 갇히지 않는지 확인합니다.
3. 제목과 원고 입력란의 이름, 역할, 현재 내용과 입력 가능 상태를 듣고 짧은 무해한 샘플만 입력합니다.
4. 예시 원고, 언어, 목소리, 읽는 속도와 음향 설정의 이름·역할·선택/값·변경 결과를 듣습니다.
5. 일괄 변환과 품질 점검 영역으로 이동해 파일 선택, 형식과 비활성화 이유를 확인합니다. 사용할 경우 권리가 있는 무해한 짧은 샘플 파일만 선택합니다.
6. 생성 또는 검사 중 진행·오류·취소·완료 상태가 실제로 적절한 시점에 읽히는지 확인합니다. 테스트하지 않았다면 미실행으로 기록합니다.
7. 결과가 실제로 있는 경우 낭독만과 음향 포함 선택, 재생·정지·다운로드의 이름 및 선택 상태를 확인합니다. 없는 결과를 있다고 가정하지 않습니다.
8. VoiceOver 실행/활성화 명령과 TalkBack 두 번 탭으로 제어를 실제 작동하고, 일반 키보드 Tab/Shift+Tab과 화면 확대 상태에서도 다시 확인합니다. 결과는 자동 PASS와 구분해 기록합니다.

## 도구 자체 확인과 알려진 한계

```sh
python3 tools/accessibility/self_test.py
```

추가 패키지 없이 실행합니다. 이 테스트는 가짜 ADB/AppleScript 응답으로 사전조건·종료코드·정리·XML 분류를 점검하고, 호스트에 `chromium`이 있으면 임시 DOM의 레이블 정상/누락도 검사합니다. Chromium이 없으면 그 항목만 SKIP입니다. `common.py`는 경로/URL/결과 처리, `safari_inspect.js`는 DOM 검사, 두 플랫폼 스크립트는 각 기기 제어, `self_test.py`는 모의 테스트입니다. JavaScript에서 ARIA 이름 전체 계산, Shadow DOM, 모든 화면과 동적 상태를 검사하지 않습니다. Android UI Automator는 기기·Chrome 버전·보이는 화면에 따라 다른 트리를 제공합니다. 이 도구는 음성을 녹음·인식하지 않습니다.
